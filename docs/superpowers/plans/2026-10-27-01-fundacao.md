# NPAC Corporation — Plano 01: Fundação

**Status:** implementado e revisado. Evidências, ajustes ao plano e limites em
[`docs/revisao-fundacao.md`](../../revisao-fundacao.md). Comandos locais de lint,
typecheck, testes e build verdes; 14 e2e verdes; `/leads` com 139 KB gzip de JS.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Monorepo funcionando com Postgres + RLS, login individual com MFA para HEADs, matriz de permissões, auditoria, API de leads que prova as regras de acesso, e a casca mobile-first do app web.

**Architecture:** pnpm + Turborepo. `apps/api` (NestJS sobre Fastify) é a única porta para o banco; `apps/web` (Next.js App Router) fala com a API pela mesma origem (rewrite `/api/*`), então cookies de sessão são first-party e não há CORS. Autorização em duas camadas: guard de permissão na API (papel) e Row-Level Security no Postgres (quais linhas cada um vê). Contatos (telefone) são criptografados por campo com índice cego para busca/duplicidade.

**Tech Stack:** Node ≥ 22, pnpm, Turborepo, TypeScript strict, NestJS + Fastify, Drizzle ORM + postgres-js, PostgreSQL 16, Better Auth (email/senha + plugin `twoFactor`), argon2id (`@node-rs/argon2`), Zod, Vitest, Supertest, Next.js (App Router) + Tailwind + shadcn/ui, Playwright, nestjs-pino, Docker Compose.

**Spec:** `docs/spec.md` (roadmap em `docs/superpowers/plans/2026-10-27-00-roadmap.md`)

## Global Constraints

- Nome do produto em toda UI/metadata/issuer do MFA: **NPAC Corporation**.
- Papéis: `HEAD`, `SDR`, `CLOSER` + flags `canProspect`, `canClose`. Nenhuma regra pode depender de nome de pessoa.
- Visibilidade: HEAD → todos; SDR → `sdr_id = eu`; CLOSER → leads com reunião não cancelada onde `closer_id = eu`.
- Faixas de renda permitidas: `R5_10K`, `R10_20K`, `R20_50K`, `R50K_PLUS`. Não existe faixa abaixo de 5k. Nunca guardar renda exata.
- Sem cadastro aberto (`disableSignUp: true`). MFA (TOTP) obrigatório para HEAD.
- Nenhum dado pessoal em `localStorage`, URL, logs ou analytics. Respostas com dado pessoal: `Cache-Control: no-store`.
- Lead não visível responde **404** (nunca 403), para não revelar existência.
- Dinheiro sempre em centavos inteiros (vale a partir do plano 03).
- Fuso de negócio: `America/Sao_Paulo`. Datas no banco: `timestamptz`.
- Fonte: Plus Jakarta Sans servida localmente via `next/font` (nenhuma chamada ao Google em runtime).
- Pré-requisito da máquina: **Docker Desktop instalado** (Postgres local e de teste).

## Review Focus

1. **Telefone em formatos variados** (`(11) 98888-7777`, `+55 11 98888-7777`, `11988887777`) tem de bater como o mesmo número na detecção de duplicado → testes na Task 2 e Task 9.
2. **Lead duplicado de outro SDR**: o RLS esconde o lead, mas o cadastro duplicado precisa ser barrado mesmo assim, sem revelar de quem é → teste na Task 9.
3. **Reunião remarcada para outro closer ou cancelada**: a Sônia deixa de ver o lead → teste na Task 5.
4. **Virada do dia em Brasília**: 23:30 BRT ainda é "hoje", mesmo com servidor em UTC → teste na Task 2.
5. **Usuário desativado** (alguém sai da empresa) perde acesso na hora, mesmo com sessão aberta → teste na Task 8.

  - Funções SQL `SECURITY DEFINER` (dono `npac_owner`, `search_path` fixo): `app_user_id() returns text`, `app_role() returns role` (lê de `"user"` onde `id = app_user_id() and active`), `closer_has_lead(lead uuid) returns boolean`, `lead_contact_taken(bidx text, insta text) returns boolean` (ignora `deleted_at not null`).

Políticas (todas as tabelas de domínio com `ENABLE` + `FORCE ROW LEVEL SECURITY`):
```
leads SELECT/UPDATE: app_role()='HEAD'
   OR (deleted_at IS NULL AND (sdr_id = app_user_id() OR closer_has_lead(id)))
leads INSERT: app_role()='HEAD' OR (app_role()='SDR' AND sdr_id = app_user_id())
leads DELETE: nenhuma (exclusão é soft delete por HEAD)
meetings SELECT/UPDATE: app_role()='HEAD' OR closer_id = app_user_id()
   OR lead_id IN (SELECT id FROM leads)   -- herda visibilidade do lead
meetings INSERT: lead_id IN (SELECT id FROM leads)
audit_log: GRANT INSERT, SELECT a npac_app; REVOKE UPDATE, DELETE, TRUNCATE
```
`GRANT SELECT, INSERT, UPDATE` nas tabelas de domínio e `SELECT` em `user` para `npac_app`.
